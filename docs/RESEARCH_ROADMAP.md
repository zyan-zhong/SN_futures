# SNInsightTerminal 研究路线图

本文档记录 SNInsightTerminal 后续研究与工程升级方向。所有方向均以“真实数据、无未来函数、成本后验证、合规展示”为前提，不承诺收益，不构成投资建议，不接入实盘交易接口。

## 1. SN 基本面数据增强

优先补强以下免费或公开数据源：

- SHFE 仓单日报、库存周报、交易排名和结算参数。
- 沪锡主力、连续合约、远近月价差和换月记录。
- 现货升贴水、基差、交割月结构和流动性指标。
- 海关锡矿砂、精炼锡、锡相关制品进出口数据。
- 国家统计局、工信部、商务部等产业与宏观公开数据。

目标：让中长期模型不只依赖历史价格，而能解释库存、供应、需求和政策变化。

## 2. LME / SHFE 跨市场联动

后续研究重点：

- LME 锡收盘、夜盘跳动、隔夜收益和波动率。
- USD/CNY、美元指数、美国利率、全球风险偏好代理。
- LME-SHFE 价差、进口窗口和跨市场领先滞后关系。
- 不同交易时段的传导差异：夜盘、日盘开盘、午后、节前。

目标：建立跨市场方向候选，而不是把外盘数据简单拼接成噪声特征。

## 3. 产业链事件知识库

需要持续沉淀事件类型和历史影响：

- 缅甸、印尼等海外产地供应扰动。
- 矿山停产、复产、出口许可和运输风险。
- 半导体、电子制造、光伏、焊料、马口铁需求变化。
- SHFE 规则、保证金、涨跌停、限仓、交割与仓单变化。
- 春节、国庆、节前夜盘暂停和节后补库行为。
- FOMC 加息、降息、利率路径和美元波动。

目标：每类事件必须记录 `available_at`，并通过事件研究评估不同周期的历史方向、波动和区间影响。

## 4. Regime-specific 模型优化

当前模型治理已支持 regime-aware 方向。后续建议按市场状态细化：

- 趋势上行低波动
- 趋势上行高波动
- 趋势下行低波动
- 趋势下行高波动
- 区间低波动
- 区间高波动
- 事件冲击
- 交割挤仓
- 流动性偏薄

目标：不同 regime 使用不同阈值、特征权重和风险约束，避免单一模型在全部行情状态下失效。

## 5. Paper Trading 与实盘前风控验收

建议在不接入真实下单的前提下建立 paper trading：

- 每次预测生成不可覆盖快照。
- 兑现后记录方向命中、区间覆盖、中枢误差和成本后收益。
- 统计强信号命中率、Brier、ECE、回撤、profit factor、break-even cost。
- 区分 active、candidate、degraded、retired。
- 每次模型晋级必须通过 promotion gate。

实盘前必须完成：

- 至少一个完整换月周期的连续跟踪。
- 多个行情 regime 下的样本外验证。
- 数据源故障演练。
- 限流、断网、缓存过期和 stale 数据降级演练。
- 合规文案与用户风险确认流程。

## 6. 专业前后端终端重构计划

建议把前端逐步从静态 JS 升级为工程化终端，但不要破坏当前 API 合同：

- 使用明确的 API schema 和类型定义。
- 七周期预测卡、图表、事件证据、模型健康、学习状态、持仓情景模块组件化。
- 增加浏览器端自动化测试和视觉回归测试。
- 图表支持历史区/预测区、事件标记、换月点、方向概率副图、区间宽度副图。
- 后端继续保持 service 层边界，避免路由文件承载业务逻辑。

目标：提升可维护性、交互稳定性和发行质量，而不是单纯美化页面。

## 7. 合规边界

必须长期坚持：

- 不承诺收益。
- 不承诺方向一定正确。
- 不输出“必须买入/必须卖出”等确定性交易指令。
- 不接入实盘交易接口。
- 不用未来函数、数据泄露或伪造指标提高胜率。
- 不用旧缓存冒充新预测。
- 所有预测、信号、报告和持仓情景仅为量化投研参考。

## 8. 推荐下一阶段 Prompt

建议下一阶段聚焦：

“在不改变后端 API 合同的前提下，为 SNInsightTerminal 建立工程化 Web 终端和浏览器自动化验收，覆盖七周期预测卡、图表、事件证据、模型健康、学习状态、持仓情景和报告预览。”
